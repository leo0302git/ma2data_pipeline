Seed file_suffixes are retrieval hints, not a hard source-format allowlist. A new
filename extension does not change a frozen group's seed. Inspect the actual profile
and determine whether its observations, targets and scientific modality support the
locked achievement. Different encodings can support the same task, but a table cannot
be treated as observed images and missing labels cannot be invented. Record concrete
scientific gaps rather than rejecting on the extension alone.

# Inputs

Use the locked seed contract, group, source profile, and source evidence IDs. The new source is mounted read-only later. Its raw contents and private labels are not part of this prompt.
The generation unit is ONE inventory source per package, possibly with several files
belonging to that source. A shared group seed fixes the task family, not a combined
dataset containing all sibling sources. Apply every scientific constraint and data
requirement to the supplied source; never demand the other group members merely
because they share the seed. Missing files required by THIS source remain blockers.
Respect submission_backend before freezing deliverables. A file-result assessment
does not automatically require submission, execution, timing or output regeneration
of Solver-authored code. Preserve the original assessed achievement and declared
result files; add no unrequested executable obligation. If program behavior is
actually required by the locked assessment, flag the missing backend. Never equate
syntax checking with verifying execution or secretly execute submitted code beside
private answers.

# Work

This phase freezes a construction PLAN, not a claim that preparation or acceptance
already passed. If a complete mathematical source needs controlled parsing or a
computed reference, specify those construction gates in changes; preparation will
inspect full bytes and compute/validate the reference. Do not reject solely because
the profile does not already contain the future private reference or a finalized
result-file schema. Define the interface from the locked assessment and backend.
Actual missing external data, undefined scientific semantics or unavailable required
facilities remain real blockers; do not invent them or assume a gate passed.

When a recovered authoring draft exists, readable files appear under exact
attempt-01/task/... and attempt-01/work/... broker paths. They are read-only prior
implementations, not authoritative requirements. Inspect them when useful and let
the CURRENT locked assessment/backend override obsolete interface claims.

Use the observed runtime_capabilities and approved_base_image before naming implementation tools.
Freeze scientific requirements and necessary interfaces, not an incidental SDK preference. Use
installed equivalent readers and algorithms when they preserve the source semantics and assessment;
for example h5py/scipy may read AnnData's HDF5 encoding without pandas/anndata. Do not require
an uninstalled package merely because it is conventional. If an exact compiler, interface or
tool version is itself assessed by the seed, preserve that requirement and flag a real missing
runtime instead of replacing the assessment. Clearly distinguish mandatory interfaces from
suggested implementation choices.

1. Define the original core assessment and the new scientific goal. State the preservation, adaptation, and reason. Choose an independently scoreable evaluation unit from the new data.
2. Map the evidence IDs to exact public and evaluator-only data roles. Define leakage-safe splits and identify any independent reference outcome. Explain any meaningful departure from the seed's metrics and deliverables.
3. Define the Solver's allowed information, measurable output, scoring rule and required environment. Name missing labels, unavailable comparisons, or unknown schema explicitly. If a source requires controlled inspection before construction, describe the inspection in `changes` so the preparation program can enforce it. Do not create unsupported scientific facts or invent published results.

# Output

Return `result_json` with nonempty `goal`, `preserved`, `changes`, `evaluation_unit`, `public_data`, `private_data`, `submission`, and `scoring` strings, and `evidence_ids` as a nonempty array of supplied evidence IDs. No file writes.

Each of these eight text fields must be at most 4000 characters. Compact prose without
dropping scientific requirements. If scope_validation_feedback is provided, repair the
specific response-shape or length error while retaining the scientific assessment.
Keep a genuine missing-data or scientific mismatch verdict as needs_review.

Preparation is one isolated /program/prepare.py execution with ONE host wall-clock
timeout and shared CPU/RAM quota. Serial child-run budgets plus extraction and audit
overhead must fit that deadline. Separate child processes do not each receive a fresh
host timeout. If using parallel methods, predeclare their shared resources and enforce
the same overall deadline. A time cap alone does not guarantee a useful comparison:
where justified, distinguish an actual first-feasible policy from a full optimization
search. Retain failed or tied methods honestly and never manufacture a worse result.


# Evidence-grounded scope

Use the actual rich source profile, including categorical counts, missingness, annotation crosswalks, feature identifiers, spatial libraries and embedded citation. Never freeze an unsupported prerequisite as an established fact. A one-sample source supports only within-source assessment unless other independent samples are supplied. If expression units/normalization are unknown, describe stored nonnegative expression values and choose a method justified for that representation, or explicitly request the missing provenance. Integer values alone do not establish raw counts. When the seed permits published-label agreement, explicitly distinguish source annotation reproduction from independent expert or experimental truth.


# Explicit comparison profile

Apply comparison_policy.mode and its rule. generated_measured explicitly adapts only the original reported-comparison admissibility rule. Preserve every scientific constraint and other verification requirement. Actual strong/weak methods must use Solver-permitted data; private-answer oracle controls are separate. Numerical calibration links alone are not scientific proof: independently inspect actual method programs, split, metric, information boundaries and execution receipts. Keep the original strict profile distinct. Never describe generated_measured as literature SOTA or strict original-rule certification.
